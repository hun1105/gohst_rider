## 2. 부하 시험 (`ai_relay_server/soak_test.py`, 신규)
가짜 rosbridge 2대 + 릴레이 + Unity 역할 클라이언트를 한 프로세스에서 300초 동안 12초 순환으로 반복:
A 수동 주행·지연 측정 → B 전방 0.3m 장애물 + 전진 시도 → C 2대 AUTO + 0.8m 만남 → D 콕핏 진입·후진 비켜주기.

| 지표 | 수정 전 (40초) | 최종 (300초) |
|---|---|---|
| cmd_vel 송신율 (로봇별) | 15.77 Hz, 초당 최소 13회 | **20.06 Hz**, 초당 최소 18회, 15회 미만 구간 0 |
| 텔레메트리 | — | 6058/6059건 (19.99 Hz), 간격 p50 53 ms · p95 78 ms · p99 90 ms, 150 ms 초과 공백 1회 |
| 영상 프레임 (가상) | — | 24.5 fps |
| 지령 → cmd_vel 지연 | p50 67 ms | p50 84 ms · p95 114 ms (1220 표본) |
| 안전 불변식 위반 | 0 | **0** (장애물·만남 구간 유예 0.3s 후 전진 지령 > 0 없음) |
| 메모리 | — | Working Set 69.0 → 75.8 MB, 추적 메모리 +2.1 MB |

- **해석 주의**: 릴레이·가짜 로봇·클라이언트가 한 이벤트 루프를 공유하므로 지연·지터는 실제 배치(PC 릴레이 ↔ Wi-Fi ↔ 로봇)와 다른 **시험 환경 상한값**이다. 실기 지연은 현장에서 별도 측정 필요.
- 지연 p50이 67 → 84 ms로 보이는 것은 수정 전 측정이 다른 시험(10회 반복)과 동시 실행된 값이라 직접 비교 불가.
- **메모리**: tracemalloc 증가 상위 5개가 모두 시험 도구(`soak_test.py`의 cmd_vel·시각·텔레메트리 기록 목록, 가짜 로봇 JSON 파싱 객체). 릴레이 모듈은 상위 항목에 없음 → 누수 징후 없음. 실기 장시간(1시간+) 운행 시 운행 이력 로그로 재확인 권장.

## 3. 발견 및 수정 (안전 루프 — Claude)
| 문제 | 원인 | 수정 |
|---|---|---|
| 제어·텔레메트리 실제 15.8 Hz (규격 20 Hz) | 루프가 "처리 후 0.05s 대기" → 주기 = 50 ms + 처리시간. 경로·탈출 계산 p50 9.4 ms · p95 13.6 ms (실측) | `CONTROL_PERIOD_S` 마감 시각 기준 고정 주기, 밀리면 기준 재설정 (따라잡기 폭주 방지) |
| 영상 JPEG 인코딩이 이벤트 루프 블로킹 | `cv2.imencode` 동기 호출 (규칙: asyncio 블로킹 금지) | `asyncio.to_thread`로 이동 |

- 워치독(0.5s)·odom(0.5s)·scan(1.0s) 판정은 시각 기반이라 주기 변경에 영향 없음. sim 로봇 위치 적분은 이제 실제 주기와 일치(이전엔 dt=0.05 가정 대비 약 20% 느리게 이동).
